# Agent Instructions

## Common guidance

- Read `CONTEXT-MAP.md` and the glossary for the work; read each relevant
  glossary when the task crosses context boundaries.
- Use quoted shell paths, including literal Next.js bracket directories.
- Fix lint/test failures; never use `git stash` to diagnose their origin.
- Preserve uncommitted work. Before undoing edits, inspect `git diff` and
  apply targeted edits; use Git undo commands only when work cannot be lost.
- Create worktrees under `/mnt/krav-azure-dev-data/.worktrees/` when that
  mount exists; otherwise use a writable temporary root outside the checkout.
- For Markdown cSpell findings, add correct technical terms, words in the
  document language, proper nouns and common contextual acronyms to the
  project dictionary; correct actual misspellings in the text.
- Track issues in `viscalyx/Kravhantering`. For multiline GitHub Markdown,
  use `gh ... --body-file -` with a single-quoted heredoc, then verify the
  body with `gh ... view --json body --jq .body`.
- Keep relevant `docs/**/*.md` aligned when behavior or workflows change.
- For user-facing functionality, workflows, roles/permissions, visible UI,
  reports, privacy/export, lifecycle or admin changes, update matching
  automated tests and manual cases. If internal-only work needs no manual
  case update, state that in the final response.
- Use the repository stack: Next.js App Router, React, strict TypeScript,
  Tailwind CSS, next-intl (`en`/`sv`), Framer Motion and Vitest; self-hosted
  Next.js with SQL Server and TypeORM as the sole database stack. Read
  `package.json` for current versions and command composition.
- Use `npm run check` for repository checks, `npm run test` for tests and
  `npm run dev` for the development server; apply scoped verification rules.

## Routing contract

- All four consumers use these routes: Codex CLI, Codex IDE extension,
  GitHub Copilot CLI and GitHub Copilot in VS Code.
- Resolve every path from the repository root, including planned files.
  Before a move, evaluate source and destination scope.
- Each row requires reading its target when its path selector matches OR
  its task condition holds. Task conditions can hold before paths are known.
  A rule within that target applies only when its own path, task, framework
  and exception conditions hold; reading does not broaden applicability.
- Select every matching row. Read the current target unless its full current
  text is already in context, and follow applicable reference pointers.
  Re-evaluate when scope, paths or instruction files change. Native Copilot
  selection can supply a target; it does not replace semantic task routing.
- Interpret bracket directory names literally. `[[]locale[]]` and `[[]id[]]`
  below denote `[locale]` and `[id]`. Braces list alternatives; `*` matches
  within one path segment and `**` spans directory levels. Native selectors
  must express the same intended path coverage.
- For work anywhere under `tests/integration/`, read
  `tests/integration/AGENTS.md`, including with nested discovery disabled.
