# Plain language

## Establish the purpose

Read the request, source text, and applicable local writing and terminology
rules. Establish what readers need to understand, decide, or do. Use the
available context before asking questions; ask only when a missing answer
would materially change the text. Continue work that does not depend on it.

For existing text, keep the requested language and tone. For new texts if the
user did not define the language, ask. Choose a structure that fits the purpose;
a short explanation need not become a guide or checklist.

## Use the text's language

If text is not English or Swedish, explain the skill is not optimized for that
language.

Preserve quoted text and exact labels in their original language, including labels
in other languages.

For technical English, apply ASD-STE100 Simplified Technical English.
This includes explanations of how systems work and instructions for setup,
operation, maintenance, or troubleshooting. For other English text, use
plain English with natural grammar and familiar wording. In mixed text,
apply ASD-STE100 to the technical passages.

For Swedish, including technical text, use klarspråk: adapt the content and
structure to the reader, use direct verbs, and explain necessary specialist
terms in natural Swedish. Use Swedish grammar and word formation rather than
translating English writing rules.

## Protect the meaning

Identify the claims, conditions, uncertainty, quantities, responsibilities,
and distinctions the text must retain. Preserve these through the rewrite.
Keep exact identifiers, commands, and interface labels; explain their meaning
in the surrounding language.

When clarity depends on a missing or conflicting fact, inspect available
evidence. Use sources appropriate to the claim and current evidence for facts
that can change. If the gap remains, ask a focused question and identify what
cannot yet be stated reliably. Keep uncertainty visible in the affected text.
Distinguish a wording improvement from a factual correction supported by
evidence. Research is needed for factual gaps, not for every wording change.

## Make the text easy to follow

- Lead with the point readers need. Order supporting information so each part
  builds on what readers already know.
- Use familiar, concrete words and direct verbs. Make actors and references
  clear when readers need to know who does what or what a pronoun refers to.
- Keep necessary technical terms. Explain unfamiliar terms at the point of
  use, with a brief definition or an example that resolves a likely confusion.
  Use the same term for the same concept.
- Let novices reach the meaning without assumed specialist knowledge. Let
  experienced readers find the precise detail without repeated introductions.
  Put depth beside the point it explains or behind a clearly named reference.
- Give each sentence a clear job and each paragraph a connected point. Split
  dense passages where it helps; retain connections between causes,
  conditions, and outcomes. Brevity alone does not establish clarity.
- Use headings, lists, or tables when they make information easier to find or
  compare. Match the amount of structure to the text.
- Remove repetition, empty introductions, and details that do not help the
  reader. Explain an essential caveat once, beside the claim it qualifies.

For text containing actions, choices, or interface instructions, read
[ACTIONS.md](ACTIONS.md) and apply only the relevant checks. Background prose
does not need added tasks or completion checks.

## Check and deliver

Read the result from two positions: a novice encountering the subject and an
experienced reader seeking an exact answer. Resolve unexplained terms, hidden
assumptions, ambiguous references, and details that obscure the main point.

Compare the result with the source and evidence. Account for every essential
claim and condition; resolve changes in meaning, certainty, or responsibility.
For new text, make the same comparison against the request and known facts.
Check that removing or moving content has not broken a dependent passage.

Finish when the reader can find the point, understand the relevant terms, and
identify any intended action without guessing, while the necessary precision
remains. Flag unresolved factual gaps instead of presenting affected text as
ready to use. This read-through is an editorial check, not proof from reader
testing.

Deliver the requested text or edits. For a review, give concrete passages,
the confusion each causes, and proposed repairs. Keep process notes separate
from the reader's text and include them only when useful to the requester.
